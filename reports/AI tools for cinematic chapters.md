# Automate the assembly, keep the directing

No tool today can design good first-person cinematic moments by itself. But the tools that can **build** those moments from a written plan are already inside this project. Your MCP server is Epic's own official Unreal MCP plugin. With AllToolsets switched on, it gives Claude Code about **340 Sequencer tools**, a StateTree toolset, and editor tools for screenshots, camera moves and play tests ([local check of the UE 5.8 install / project file, 2026-11-14](file:///F:/UE_project/YggdrasilsPeak/YggdrasilsPeak.uproject)). The best study of AI-made cutscenes shows where the line is. Claude used the tools **100% correctly**, but scored only **50.2 out of 100 on cinematic quality** ([Cutscene Agent, arXiv 2026](https://arxiv.org/html/2604.25318v1)). So the plan that works is simple: Claude assembles, you direct. Build one "beat pipeline" once. It has a small camera component that guides the player's eye, story beats stored in tables, radio lines picked by rules, dialogue in Ink text files, voices made offline with ElevenLabs, and NPC motion from Epic's free webcam mocap plugin. After that, each chapter becomes text and data that Claude writes, places and checks. Almost everything is free with the engine. Voices cost roughly **$100–400 for the whole game** (estimate). No AI runs while the game plays, so the laptop pays no performance cost. My estimate: **4–6 weeks to build the pipeline, then about 2–3 days for a normal chapter and 4–6 days for a set-piece chapter**, instead of about a week. Because of the build time, the first pass through all 17 chapters saves little; the big win is that every later revision costs hours, not days. Avoid AI characters that talk live, the experimental Gameplay Cameras plugin, research camera-path models, and any voice or motion model with a non-commercial licence.

## Key words in plain English

| Word | What it means here |
|---|---|
| MCP | Model Context Protocol. A standard way for an AI agent (Claude Code) to call tools inside another program, here the Unreal Editor. |
| Toolset | A group of MCP tools that Epic ships for one area, such as Sequencer or StateTree. |
| Sequencer, Level Sequence | Unreal's timeline editor for cutscenes, and the asset file it saves. |
| Camera Modifier | A small C++ layer that changes the player's camera each frame: a small turn, a shake, a field-of-view change. |
| Beat | One story moment: when it fires, and what the player sees and hears. |
| Storylet | A small story piece that becomes available when the game state matches its conditions. |
| Ink, Inkpot | A plain-text language for branching dialogue, and the free plugin that runs it in Unreal. |
| TTS | Text-to-speech. An AI voice reads written lines. |
| Mocap, retarget | Motion capture (recording body movement), and copying that motion onto a different skeleton. |
| StateTree, Smart Object | Unreal systems that decide what an NPC does, and marked spots in the level where it does it. |
| LLM | Large language model, the kind of AI behind Claude. |

## Your editor already holds about 340 cutscene tools

Start with what is already installed. The project's `.mcp.json` points Claude Code at `http://127.0.0.1:8000/mcp`. The project file switches on Epic's **Unreal MCP** plugin (Experimental), **AllToolsets**, **EditorToolset**, **StateTree** and **Terminal**. So the server you use is Epic's own, not a community one ([local check of the UE 5.8 install / project file, 2026-11-14](file:///F:/UE_project/YggdrasilsPeak/YggdrasilsPeak.uproject)). The engine ships 27 toolsets. For chapters, the useful ones are AnimationAssistantToolset (Sequencer and animation), SequencerAnimMixerToolset, StateTreeToolset, ConversationToolset, MetaHumanGenerator, NiagaraToolsets and PCGToolset. EditorToolset can capture the viewport, set the camera, start and stop Play-In-Editor, select actors and read the log ([local check of the UE 5.8 install, 2026-11-14](file:///E:/UE5.8/UE_5.8/Engine/Plugins/Experimental/Toolsets)). The Sequencer family alone has about 340 tool functions. They create Level Sequences, add actors and spawned cameras, add any track type, set camera cuts, add event triggers, put keys on channels, bake, and import or export FBX ([local check of Epic's sequencer.py](file:///E:/UE5.8/UE_5.8/Engine/Plugins/Experimental/Toolsets/AnimationAssistantToolset/Content/Python/animation_toolset/toolsets/sequencer.py); [Schepetkov skills](https://github.com/Schepetkov/claude-skills-game-UE)). Epic ships test files for these tools, which suggests Epic tests them in its own builds ([local check of the tests folder](file:///E:/UE5.8/UE_5.8/Engine/Plugins/Experimental/Toolsets/AnimationAssistantToolset/Content/Python/animation_toolset/tests/)). **You do not need a new MCP server.** One honest caveat: the server was offline during this research because the editor was closed. Nobody has run these Sequencer tools live in this project yet.

What can an AI do with such tools? The clearest answer comes from Cutscene Agent (Kuaishou, April 2026). The team built high-level cutscene tools on an Unreal MCP server: add a character, add an animation, add a camera, apply a camera template, take a screenshot. Then they tested 8 AI models on 65 scenes. **Claude Opus 4.6 scored 100%** on picking the right tool, giving valid inputs, finishing every step and calling tools in the right order, and 96.4% on camera coverage. But its **cinematic and story quality was 50.2 out of 100**. That was still the best score; GPT-5.4 got 42.4. Scenes with three characters were the hardest. The typical errors were skipped steps, invented asset names, overlapping animations, and moments with no active camera ([Cutscene Agent](https://arxiv.org/html/2604.25318v1)). The lesson is direct: **AI is reliable at assembly and weak at taste.**

Field reports say the same. FINAL CUT was made in **3 days** by one person with Claude Code driving Unreal through Epic's MCP. The agent built logic, levels, lights, cameras, materials and UI, and ran an automatic play test after every change, over about 60 commits. Its maker's rules: after two honest attempts, choose a simpler design, and keep the human as director ([FINAL CUT devlog](https://mullin-works.itch.io/final-cut/devlog/1776695/devlog-2-how-one-human-and-an-ai-agent-made-final-cut-in-3-days)). Puget Systems tested UE 5.8 with Claude. A six-room greybox took 5 minutes. But new walking controls failed, and a claimed fix changed nothing. Each turn took **5–15+ minutes**, and one morning used about **15% of a weekly token allowance**. Their advice was to use MCP "to speed up iteration, not to fill gaps in knowledge" ([Puget Systems](https://www.pugetsystems.com/blog/2026/07/09/unreal-engine-mcp-hands-on-testing-ai-inside-the-editor/)). Other users saw agents act before looking, retry in loops, and report checks that never happened ([Algosyntax](https://store.algosyntax.com/blog/ai-assistants-mcp-unreal-engine-5-8)). Another project found agents bad at placing props by eye ([daily.dev summary](https://daily.dev/posts/i-built-my-dream-game-in-72-hours-assets-by-ai-gameplay-by-claude-code-eedcr1c11)).

So how do you get close to "automatic"? Three steps. **First, install Epic's official Claude Code plugin**, `unreal-engine-skills-for-claude-code`, with `/plugin install unreal-engine-skills-for-claude-code@claude-plugins-official` ([Claude Directory](https://www.claudedirectory.org/plugins/unreal-engine-skills-for-claude-code)). It teaches Claude Epic's own safety rules. Save before and after big edits, because MCP edits cannot always be undone. Run dependent calls one at a time. Treat any unclear result as a failure, because some failures return no error ([Epic SKILL.md](https://github.com/EpicGames/unreal-engine-skills-for-claude-code-plugin/blob/main/skills/unreal-mcp/SKILL.md)). **Second, write your own toolset in Python.** Epic's server accepts custom toolsets. The function names and docstrings become the tool descriptions Claude sees ([Seele AI guide](https://www.seeles.ai/resources/blogs/unreal-engine-5-8-mcp-custom-toolsets-python-cpp-guide)). Project skills also take priority over generic ones ([Epic SKILL.md](https://github.com/EpicGames/unreal-engine-skills-for-claude-code-plugin/blob/main/skills/unreal-mcp/SKILL.md)). A small `YggCinematicTools` set, with tools like `stage_beat`, `place_look_trigger`, `place_npc_on_route`, `build_cutscene_from_shotlist` and `capture_shot_preview`, copies the Cutscene Agent design. It also hides known traps. For example, since 5.5–5.6 a Level Sequence must be open in the editor before Python can add spawned actors to it ([UE forum](https://forums.unrealengine.com/t/add-spawnables-to-sequence-in-5-6/2658807)). **Third, make every tool read back what it changed and take a viewport screenshot.** Then you judge the frame. This matches your rule that Claude verifies by measurement and you make the visual call. The community `ue-cinematics` skill (MIT licence, targets UE 5.8) is worth reading for craft notes. But it has 2 stars and no proof of shipped cutscenes ([Schepetkov skills](https://github.com/Schepetkov/claude-skills-game-UE)).

Other servers and paid tools add little. The early popular community servers have **no** Sequencer tools ([runreal](https://github.com/runreal/unreal-mcp); [flopperam](https://github.com/flopperam/unreal-engine-mcp)). ChiR24/EngineWire (MIT, UE 5.0–5.8) is the best backup if Epic's plugin breaks ([GitHub](https://github.com/ChiR24/Unreal_mcp)). Aura costs $10, $40 or $200 a month and is built on Claude, but no Sequencer feature was found in its materials ([Aura 15](https://www.tryaura.dev/updates/introducing-aura-15)). An Aura plugin folder exists in your engine install, status unknown ([local check of the UE 5.8 install, 2026-11-14](file:///E:/UE5.8/UE_5.8/Engine/Plugins/Marketplace/Aura)). The engine also contains AIAssistant and CharacterAI (Beta) plugins, but no documentation was found for what they do, so do not plan around them. The real next step is **UE 5.9**, in Preview since 9 November 2026. It adds an in-editor Unreal Assistant, scene-capture and console toolsets, AnimGen and NVIDIA Kimodo that put generated motion straight into Sequencer, and ElevenLabs voice ([UE 5.9 Preview release notes](https://dev.epicgames.com/documentation/unreal-engine/unreal-engine-5-9-release-notes)). It is a preview, so for a thesis project it belongs in "try later".

## In first person, the best camera work never takes the camera

Thirty years of research on automatic camera work exist, but almost none of it fits your game. Early systems stored film rules as small state machines called idioms ([DCCL and Virtual Cinematographer, 1996](https://www.researchgate.net/publication/2329036_Declarative_Camera_Control_for_Automatic_Cinematography)). Later ones planned shots from story structure ([Jhala & Young, AAAI 2005](https://cdn.aaai.org/AAAI/2005/AAAI05-049.pdf)). Since 2020, models learn camera paths from films ([survey, 2025](https://arxiv.org/pdf/2506.00974)). In 2026, LLM agents build shots from simple moves such as dolly, orbit, crane, pan and tilt ([CinemaTraj](https://arxiv.org/abs/2607.26910v1); [Auteur](https://arxiv.org/html/2606.01900)). Cine-AI even generates cutscenes in the style of famous directors, but only in Unity ([Cine-AI, CHI PLAY 2022](https://arxiv.org/abs/2208.05701)). **All of these film characters from an outside camera.** No paper applies them to a first-person game camera. Running such models while the game plays would also break your performance-first rule. Keep one idea only: **an AI picks from a small library of tuned camera pieces, and simple code keeps them safe.** Claude can do that picking offline, when it writes a chapter's data.

Shipped first-person games show what those pieces should be. Valve's Half-Life: Alyx commentary is the best record. A **look trigger with a timer** makes sure the player sees a moment: it fires when they look, or when time runs out. **Sound comes first**: players missed a train crash until Valve added distant train noise and a sharp bang. A **glowing red sign** leads the eye by contrast. A great view works because **scale objects** fill the space between the player and the far landmark. Long explanations were **cut into pieces** across the walk. Radio talk plays while the player's hands are busy with levers. Hiding a character in shadow **cut animation work** and helped the schedule. Valve also kept only the voiced reactions that almost every player shared ([Half-Life: Alyx developer commentary](https://combineoverwiki.net/wiki/Developer_commentary/Half-Life:_Alyx)). After restless playtesters, Valve made its story scenes much shorter ([Game Informer](https://www.gameinformer.com/index.php/interview/2020/03/23/valve-talks-half-life-alyx-and-why-arms-dont-work-in-vr)). The climbing game Cairn adds a second lesson. It has no hand-made animation, only IK and procedural motion. One reviewer's most dramatic moment was an **unscripted fall** when the climber collapsed from thirst ([Game Developer on Cairn](https://gamedeveloper.com/design/cairn-s-manual-climbing-system-is-like-a-vertical-death-stranding-)). Your game already has ropes, body effects and weather. Often the best "cinematic" is to frame those systems well: a radio voice reacts, the camera holds for a second, a sound lands.

That points to one reusable C++ component, an **Attention Director**, built from Camera Modifiers on your existing first-person camera. It needs seven pieces. *SoftLookAt* gives a capped nudge toward a target and lets go the moment the player moves the mouse. *FOVPulse* briefly widens or narrows the view. *PlayCameraAnim* plays a short motion curve on top of the player's view, like a 0.6-second jolt when the rope catches. *DOFFocusOn* pulls focus to a target. *LookTrigger* checks the view cone, distance and line of sight, with a timer fallback. *AudioLure* plays a sound at a target to turn the head. *Beacon* makes a light or glow pulse on a target. Add a library of 10–15 camera shakes from Unreal's built-in Perlin, Wave, Composite and Sequence patterns, which you can preview in the editor ([Epic: Camera Shakes](https://dev.epicgames.com/documentation/en-us/unreal-engine/camera-shakes-in-unreal-engine)). With Claude, the component is roughly **3–5 days of work** (estimate). Every piece is just numbers in a data row, so a chapter places pieces instead of building them. No published cost figures exist for modifiers and shakes in 5.8, so measure them once with your play-session monitor.

Avoid two tempting paths. The **Gameplay Cameras plugin** looks like the perfect "camera director". But in 5.7 it was still Experimental, about 98% written by one Epic developer, and it broke its asset format in every release ([Chabant, 5.7 notes](https://ludovic.chabant.com/blog/2025/11/14/ue5-gameplay-cameras-upgrading-to-5-7/)). Its status in 5.8 could not be confirmed. Forum users also found that first-person FOV settings stopped working with the Lyra and Game Animation Sample camera setups ([UE forum](https://forums.unrealengine.com/t/5-5-first-person-rendering-fov-with-cameramanager-lyra-or-gasp/2224698)). The second trap is **Sequencer camera cuts** in normal play. A cut breaks the feeling of being there. Save cuts for out-of-body moments: the summit-night prologue, a death or rescue replay. When you blend from a sequence back to the player camera, one known pop is fixed by ticking **Override Aspect Ratio Axis Constraint** on both cameras ([UE forum](https://forums.unrealengine.com/t/blending-from-level-sequence-to-gameplay-camera-causes-instant-pop-despite-matching-settings/2686528)). Then follow a few rules. Take full control only for a fall, a faint or a death, and for no more than 1–2 seconds. Start and end every takeover at the player's exact eye position. Keep some look input during a nudge. Never take control during dangerous climbing. These rules are design judgement drawn from Alyx and from Journey's camera designer, who warned that dynamic cameras are the hardest to design and simpler is fine ([Vice on John Nesky](https://www.vice.com/en/article/lights-camera-distraction-the-problem-with-virtual-camera-systems)). They are not measured limits.

## Story beats scale as rules and plain text, not as scenes

The proven way to make a lot of reactive story cheaply comes from Valve. Its dynamic dialogue system, used in Left 4 Dead and later games, matches **hundreds of facts about the world against thousands of lines** ([GDC 2012, Elan Ruskin](https://gdcvault.com/play/1015317/AI-driven-Dynamic-Dialog-through)). The most specific matching rule wins, and simpler rules act as fallbacks. Writers can add lines easily, and characters seem aware of the situation without any planning AI ([Emily Short on the talk](https://emshort.blog/2012/03/16/gdc-2012-talk-on-dynamic-dialogue/)). One developer who copied the idea expected about **1,000 rules and 100 events** to cover his whole game ([Radiator blog](https://www.blog.radiator.debacle.us/2012/07/rule-databases-for-contextual-narrative.html)). Storylets work the same way: small story pieces that unlock when the state is right ([Emily Short, "Beyond Branching"](https://emshort.blog/2016/04/12/beyond-branching-quality-based-and-salience-based-narrative-structures/); [Kreminski & Wardrip-Fruin](https://mkremins.github.io/publications/Storylets_SketchingAMap.pdf)). This is how your "climb writes its own journal" idea scales to 17 chapters.

The pipeline needs three tables. **World Facts** hold the state: altitude, oxygen, weather realm, hours awake, companion distance, rope clipped, "serac warning already given". Your body, weather and rope systems write these facts. **Line rules** say who speaks, on what event (a slip, a summit view, idle time), under which conditions, which line plays, its cooldown, and which facts it writes back so nothing repeats. **Beat rows** say which chapter, how the beat triggers (a volume, a look trigger, a fact threshold, a time), its conditions, and its actions: start a radio talk, send a companion to a spot, call the Attention Director, play a lure, change the light, or play a rare Sequencer clip. Claude writes these rows from your chapter design. An editor Python script then places the triggers along the route, the same way your camp props and rocks were placed. A checker script then confirms that every fact is written somewhere, every line has audio, and no beat is unreachable. inkle built this kind of automatic testing into its own writing work ([Emily Short on Heaven's Vault](https://emshort.blog/2019/07/23/heavens-vault-inkle/)). Before any polish, play each chapter as a **"radio play" pass**: temporary voices or subtitles, rough triggers, the whole chapter end to end. What Remains of Edith Finch was built the same way, from 13 separate prototypes developed one after another ([Game Developer](https://www.gamedeveloper.com/design/video-weaving-13-prototypes-into-1-game-for-i-what-remains-of-edith-finch-i-)).

For conversations, use **Ink with the Inkpot plugin**. Ink is plain text, so Claude can write it, check it and compare versions in git. Inkpot is free and open source. The Chinese Room made it for Bloodlines 2 work. It supports UE 5.4 or later, includes the Blotter debugger for watching story variables while you play, needs .NET 5 to compile scripts, and must sit in the project's plugin folder ([Inkpot on GitHub](https://github.com/The-Chinese-Room/Inkpot)). It does not name 5.8, so test a compile first. inkle used Ink for Heaven's Vault, which has nearly 30,000 lines ([TechRaptor](https://techraptor.net/content/heavens-vault-joseph-humfrey-inkle-interview)). Yarn Spinner is also plain text and has storylets built in. But its Unreal version is an alpha that its makers say not to ship with, it needs UE 5.7 or later, and its licence bans using it to train AI ([Yarn Spinner docs](https://www.yarnspinner.dev/docs/unreal/01-installation/)). articy:draft X FREE allows commercial use up to 700 objects, but it is a visual tool that Claude cannot easily edit ([articy](https://www.articy.com/en/articydraft/free/)). Epic's ConversationToolset only reads dialogue graphs (lists nodes and speakers), so it is not an authoring tool ([local check of the UE 5.8 install, 2026-11-14](file:///E:/UE5.8/UE_5.8/Engine/Plugins/Experimental/Toolsets/ConversationToolset/Content/Python/)). For the shape of your dialogue, copy Firewatch. Its walkie-talkie talk starts when the player looks at something. It began as a bark system full of interruptions and became long conversations that can stop and restart ([GDC 2017, Firewatch](https://gdcvault.com/play/1024000/Do-You-Copy-Dialog-System)). A reviewer noted this design makes new dialogue cheap to add ([PC Gamer](https://www.pcgamer.com/firewatchs-wyoming-fosters-a-bigger-weirder-adventure-than-i-expected)). It fits Dr. Hale on the radio, the Kovac team mostly on the radio, and Nima in person.

NPC staging follows the same "data, not scenes" idea. Place **Smart Objects** at rope anchors, belay stances, tent doors and viewpoints. A Smart Object holds no logic. It only tells an NPC what can be done there, and stops two NPCs from using it at once ([Epic: Smart Objects](https://dev.epicgames.com/documentation/unreal-engine/smart-objects-in-unreal-engine---overview?lang=en-US)). A **StateTree** then gives each companion states such as follow on the rope, wait at the anchor, lead, act at a Smart Object, and talk to the player ([Epic: StateTree](https://dev.epicgames.com/documentation/en-us/unreal-engine/overview-of-state-tree-in-unreal-engine)). Your project already has the StateTree toolset, so Claude can read and edit these trees through MCP ([local check of the UE 5.8 install / project file, 2026-11-14](file:///F:/UE_project/YggdrasilsPeak/YggdrasilsPeak.uproject)). Design spaces so companions keep a natural distance and never block the route, as Valve did in Alyx ([Alyx commentary](https://combineoverwiki.net/wiki/Developer_commentary/Half-Life:_Alyx)). Keep the companion close so they never feel like a burden, as Naughty Dog did with Ellie ([Game Developer](https://www.gamedeveloper.com/design/ellie-s-buddy-ai-in-i-the-last-of-us-i-explained-at-gdc-2014)). Because multi-character scenes were the hardest test for AI agents, use fixed staging templates, not free placement ([Cutscene Agent](https://arxiv.org/html/2604.25318v1)).

Do **not** let an LLM write dialogue while the game runs. Respected narrative designers call LLM chatbot NPCs boring, and argue they only work when wrapped in hand-made design ([Rock Paper Shotgun](https://www.rockpapershotgun.com/horrible-boring-and-cheap-experts-pan-new-chatbot-npcs-but-some-leave-room-for-optimism)). inkle's Jon Ingold says he has barely used generative AI ([Creative Bloq](https://www.creativebloq.com/3d/video-game-design/how-indie-game-dev-opinions-on-generative-ai-have-changed)). Cloud options such as Convai need a network connection ([AI wiki review](https://artificial-intelligence-wiki.com/industry-ai/ai-in-gaming/convai-character-ai-guide/)). NVIDIA's on-device ACE plugins list only UE 5.5–5.7 ([NVIDIA ACE](https://developer.nvidia.com/ace-for-games)), and any model running on the player's machine adds memory load to a game that already uses 10–12 GB of RAM. Steam also requires guardrails and in-game reporting for content made live ([PC Gamer](https://www.pcgamer.com/valve-updates-its-steam-policy-on-ai-so-it-can-release-the-vast-majority-of-games-that-use-it)). Live AI can also drift from your tone of quiet awe and fate. Use Claude when writing, not when playing.

## Voices and bodies now cost dollars, but licences decide

For voices, **ElevenLabs on a paid plan** is the safe choice for a commercial Steam game. The Free plan does **not** allow commercial use. Starter is $6 a month, Creator $22 and Pro $99 ([ElevenLabs pricing](https://elevenlabs.io/pricing)). Through the API, the top models (v4, v3) cost **$0.08 per 1,000 characters** ([ElevenLabs API pricing](https://elevenlabs.io/pricing/api)). **Nepali is supported** in v4 and v3, and Hindi in more models. Tibetan and Sherpa are not listed ([ElevenLabs models](https://elevenlabs.io/docs/overview/models)). Text to Dialogue makes multi-speaker scenes up to 2,000 characters per request, with emotion tags written inside the text, such as whispers or sighs ([ElevenLabs Text to Dialogue](https://elevenlabs.io/docs/overview/capabilities/text-to-dialogue)). A rough sum: one hour of speech is about 54,000 characters, so about **$4.30 per finished hour**, or **$13–22 with 3–5 takes per line**. If the game has 2–4 hours of spoken lines, that is roughly **$100–400 in total**. These sums are my calculation, not a quote. The real cost is your listening time. The workflow: Ink lines carry IDs; a script sends each line to ElevenLabs with a fixed voice per character; it saves several takes; **you listen and pick by ear**, as you do for every sound; then a UE Python script imports the winners. A Fab plugin can also generate voice inside the editor ([Fab listing](https://www.fab.com/listings/679ff8f4-a931-4af1-a7ad-1949c2418576)). Lama chants and prayers should come from licensed real recordings or a person who agrees to be recorded.

Voice companies die fast, so never depend on them at runtime. Replica Studios shut down on 30 June 2025 and stranded projects ([MultiLingual](https://multilingual.com/replica-studios-shutdown-2025/)). Resemble AI left voice generation in August 2026 ([Resemble](https://www.resemble.ai/resources/why-a-former-voice-ai-company-went-all-in-on-deepfake-detection)). OpenAI's TTS models shut down on 6 January 2027 ([OpenAI docs](https://developers.openai.com/api/docs/guides/text-to-speech)). Keep every WAV, voice ID and setting in the repo. Open-source voices are a trap unless you check the model licence. Kokoro, Qwen3-TTS, CosyVoice and Dia are Apache 2.0 and fine for commercial use, but none was confirmed to speak Nepali, and Dia is English only. **XTTS v2, F5-TTS weights, Fish Audio S2 Pro, IndexTTS and VibeVoice are non-commercial or research-only** ([yaps.ai licence check](https://www.yaps.ai/blog/best-local-tts-models); [Cartesia guide](https://www.cartesia.ai/learn/open-source-tts)).

Players and Steam need care. Since 16 January 2026, Steam does not ask you to disclose code assistants such as Claude Code. It does ask you to disclose AI content that players see or hear, including sound and story, and the note appears under "About This Game" ([Game Developer](https://www.gamedeveloper.com/business/valve-tweaks-and-clarifies-ai-disclosure-rules-for-steam); [Notebookcheck](https://www.notebookcheck.net/Steam-updates-AI-disclosure-form-requiring-developers-to-report-visible-and-in-game-AI-but-not-background-tools.1206103.0.html)). So AI voices and AI-drafted lines that ship must be disclosed. Player mood is harsh. In one late-2025 survey, **85% of players were negative** about generative AI in games, and 77–83% disliked AI-written quests and dialogue ([Quantic Foundry via GamesMarket](https://www.gamesmarket.global/quantic-foundry-most-gamers-are-negative-about-the-use-of-gen-ai-in-video-games)). ARC Raiders got 2 out of 5 from Eurogamer, largely over AI voices ([80.lv](https://80.lv/articles/eurogamer-s-2-5-arc-raiders-review-splits-the-gaming-community/)). One indie game was even attacked for using AI voices when the voice was really the developer's wife ([Dexerto](https://www.dexerto.com/gaming/indie-dev-accused-of-using-ai-voice-acting-in-steam-game-reveals-it-was-actually-his-wife-3410085/)). The 2025 SAG-AFTRA game agreement binds only employers who sign it, so fully designed voices carry no union duty. But never prompt a voice with a real actor's name, and get written consent if a real person's voice is used ([FKKS on the agreement](https://technologylaw.fkks.com/post/102mewu/inside-the-new-sag-aftra-interactive-media-agreement-new-standards-for-ai-and-di)). Four hedges help. A radio filter hides small TTS flaws and suits the Firewatch model. Keep the most emotional lines as candidates for a human recording later. Offer a subtitles-only option. Write a specific, honest disclosure.

For body animation, the 2026 game-changer is Epic's **MetaHuman Animator Markerless Motion Capture plugin**. It is **free, including for commercial projects**, runs locally on Windows with UE 5.8, and turns one webcam or phone video into body, finger and face animation ([CG Channel](https://www.cgchannel.com/2026/06/get-the-free-metahuman-animator-markerless-mocap-plugin/)). It is Experimental, and Python and Blueprint automation plus a batch API are available ([MetaHuman 5.8 notes](https://dev.epicgames.com/documentation/metahuman/metahuman-5-8-release-notes-in-unreal-engine?lang=en-US)). Early tests found floating feet and worse results with a moving camera, so film yourself with a fixed camera and plan a foot-lock pass ([CG Channel](https://www.cgchannel.com/2026/06/get-the-free-metahuman-animator-markerless-mocap-plugin/)). Nobody from Epic has yet answered whether its runtime models can ship inside a game, so solve in the editor and ship only the baked animation ([UE forum](https://forums.unrealengine.com/t/licensing-question-shipping-metahuman-animator-markerless-motion-capture-runtime-models-in-a-steam-game/2839692)). Claude can script the rest: process the clip, then batch-retarget it onto your skeletons with `IKRetargetBatchOperation` ([Epic Python API](https://dev.epicgames.com/documentation/en-us/unreal-engine/python-api/class/IKRetargetBatchOperation)). One vendor reports a 45-second dialogue cutscene in 4–6 hours with this kind of pipeline. That vendor sells related tools and did not measure carefully ([StraySpark](https://www.strayspark.studio/blog/ai-mocap-indie-developers-2026-comparison)). For motion from text, **NVIDIA Kimodo's SOMA models allow commercial use with attribution** and need under 3 GB of GPU memory if the text encoder runs on the CPU. But its SMPL-X model is research-only, and it was built on Linux. Its makers expect Windows to work, especially in Docker, but have not promised it ([Kimodo README](https://raw.githubusercontent.com/nv-tlabs/kimodo/main/README.md)). Cascadeur Indie costs $96 a year below $100k revenue and helps clean feet and hands; its free plan is non-commercial and cannot export FBX ([Cascadeur plans](https://cascadeur.com/plans)). Uthana charges $0.06 per second for video-to-motion, includes commercial use, and has an API ([Uthana pricing](https://uthana.com/pricing)). **Avoid research motion models trained on AMASS** (MoMask, MDM, MotionGPT), because the AMASS licence bans commercial use ([AMASS licence](https://amass.is.tue.mpg.de/license.html)). Avoid Tencent HY-Motion too: it needs 24–26 GB of GPU memory ([GitHub](https://github.com/Tencent-Hunyuan/HY-Motion-1.0)), and its licence reportedly excludes the EU, UK and South Korea ([GitHub issue](https://github.com/Tencent-Hunyuan/HY-Motion-1.0/issues/49)). For walks, idles and gestures, Mixamo is royalty-free ([Adobe community FAQ](https://community.adobe.com/questions-696/mixamo-faq-licensing-royalties-ownership-eula-and-tos-589400)), and Epic's Game Animation Sample is updated for 5.8 but licensed for Unreal projects only ([Epic](https://www.unrealengine.com/tech-blog/download-the-latest-game-animation-sample-project-now-updated-for-ue-5-8); [UE forum](https://forums.unrealengine.com/t/what-can-i-do-with-game-animation-sample-that-recently-was-at-100-off/1903980)).

Faces are cheaper still. **MetaHuman Animator audio-driven animation** is free, works in UE 5.6+, turns any voice line into facial animation with mood, blinks and head motion, and runs in batches ([Epic: audio-driven animation](https://dev.epicgames.com/documentation/en-us/metahuman/audio-driven-animation)). Characters that are not MetaHumans need their face curves mapped to their own shapes ([Unreal Fest 2025 talk](https://forums.unrealengine.com/t/talks-and-demos-using-the-metahuman-ecosystem-for-non-metahuman-animation-unreal-fest-orlando-2025/2674022)). NVIDIA's Audio2Face plugin lists only up to UE 5.6 ([NVIDIA ACE](https://developer.nvidia.com/ace-for-games)), and Meta's OVRLipSync is end-of-life ([Meta docs](https://developers.meta.com/horizon/documentation/unreal/audio-ovrlipsync-unreal/)). On a laptop, MetaHumans are heavy. One forum user saw 24 fps drop to 14 near a MetaHuman face ([UE forum](https://forums.unrealengine.com/t/why-are-metahumans-so-heavy-to-run/627864)), and Epic itself recommends hair cards and a higher minimum LOD on weaker hardware ([Epic: MetaHuman LODs](https://dev.epicgames.com/documentation/metahuman/controlling-metahuman-levels-of-detail-lods-in-unreal-engine)). First person helps here: faces appear briefly, often behind goggles and hoods. Use MetaHumans as **capture targets**, retarget the motion onto your lighter NPC meshes, and keep full MetaHumans for close moments only. MetaHumans are free below $1M revenue, but their licence bans using them as AI training data ([Digital Production](https://digitalproduction.com/2025/06/05/metahumans-graduate-ready-for-unity-godot-and-the-fab-cash-register/)).

## Conclusion: the practical plan

The research changes what "automatic" should mean for this project. No tool designs a good moment. But almost every slow step **after** design (placing triggers, wiring beats, building sequences, generating voices, solving mocap, checking for errors) can now be handed to Claude through tools you already have. The speed-up does not come from AI creativity. It comes from three boring things: **reusable pieces, text formats Claude can write, and scripts that place everything**. The AI's weakest skill, taste, stays with you. Its strongest skills, exact tool calls and tireless checking, cover the repetitive work. So the bottleneck moves to your writing, your ears and your playtests. That is where it should be.

**Adopt now**

| Tool | Cost | Use it for |
|---|---|---|
| Epic Unreal MCP + AllToolsets (already on) | Free | Sequencer, StateTree, screenshots, play tests |
| Epic's Claude Code skills plugin | Free | Safe MCP habits |
| Own `YggCinematicTools` toolset + project skills | ~1 week (estimate) | One call per beat or shot |
| Attention Director + shake library (C++) | ~3–5 days (estimate) | All first-person camera moments |
| World Facts, beat rows, line rules, checker | ~2–3 weeks (estimate) | Story beats as tables |
| Ink + Inkpot | Free | All conversations as text |
| ElevenLabs Creator or Pro, only in voice months | ~$100–400 total (estimate) | Offline voices, Nepali words |
| MetaHuman markerless mocap + audio-driven face | Free | NPC acting from your webcam |
| Mixamo + Game Animation Sample | Free | Walks, idles, gestures |

**Try later**

| Tool | When |
|---|---|
| UE 5.9 (AnimGen, Kimodo in Sequencer, scene-capture and console toolsets) | After it leaves Preview |
| Kimodo SOMA on its own | If text-to-motion is needed before 5.9 |
| Cascadeur Indie ($96/year) | When mocap feet or hands need cleanup |
| Uthana (pay per second) | As a mocap backup with an API |
| MetaHumanGenerator toolset | To let Claude create NPC faces |
| Gameplay Cameras plugin | Only if Epic marks it Beta, or in UE6 |
| Yarn Spinner for Unreal | When it leaves alpha |

**Avoid**

| Tool | Why |
|---|---|
| Live AI NPCs (Convai, Inworld, NVIDIA ACE, local LLM plugins) | Tone drift, cost, GPU memory, Steam guardrails |
| Research camera-path models | Third-person, research code, runtime cost |
| Non-commercial voice and motion models | Licence forbids a Steam release |
| Any cloud voice called at runtime | Vendors shut down |
| Paid general agents for cinematics | Duplicate what you already have |
| Full MetaHumans with strand hair on every NPC | Laptop frame rate |

**Time per chapter after the pipeline exists (ESTIMATE, not measured)**

| Step | Who | Time |
|---|---|---|
| Beat sheet and words | You; Claude drafts options | 0.5–1 day |
| Rows, Ink file, placement, checker | Claude; you review | 0.25 day |
| Voice takes, listen and pick | Claude makes; you listen | 0.25–0.5 day |
| Camera moments tuning | You; Claude changes numbers | 0.25 day |
| Playtest and fixes | You and Claude | 1 day |
| New NPC acting, set-piece chapters only | You record; Claude processes | +1–2 days |
| Out-of-body cutscene, set-piece chapters only | Claude builds; you judge | +0.5–1 day |
| **Normal chapter** | | **about 2–3 days** |
| **Set-piece chapter** (prologue, summit, rescue) | | **about 4–6 days** |

These numbers cover the story layer on the route you already built: beats, camera, dialogue, voices and NPC acting. New terrain or art is extra. Be honest about the total maths. With a one-time build of 4–6 weeks, a first pass through all 17 chapters takes about the same time as a week per chapter today, or only a little less. The real payoff comes after. Every chapter will change after playtests, and a chapter made of data and text costs hours to change, not days. Chapters also get voices, companions and camera moments that a hand-made week would not include. And rotation chapters that revisit places can reuse pieces and drop toward 1–2 days. To start saving sooner, do not build everything first. Build the core in about two weeks: install the skills plugin, test-compile Inkpot on 5.8, and make World Facts, beat rows, LookTrigger, SoftLookAt and AudioLure. Then add each other piece the first time a chapter needs it. That core fits before the December interim review. Then rebuild Chapter 1 (the 44-minute design) with the pipeline, time every step, and replace these estimates with your own numbers.
