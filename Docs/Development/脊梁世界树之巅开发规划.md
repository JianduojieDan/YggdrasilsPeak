# 脊梁世界树之巅开发规划与任务清单

探险 生存 极限运动 叙事冒险

版本 1.0    编制日期 2026年10月5日    项目 YggdrasilsPeak

这份文档用于把现有场景和开始菜单推进成一款能够从山脚探索到山顶、管理资源、应对灾害并完成三种结局的游戏。它同时包含完整目标和首个可玩版本的边界，供后续逐项实施与验收。

建议下一步制作基础生存组件和最小 HUD，再接入背包、吃喝和营地。先完成一段二十至三十分钟的登山生存流程，再扩展高海拔、极限运动和神话剧情。时长是体验目标，不是已经测得的数据。

依据包括用户提供的《游戏设定.docx》、本次连接的 F 盘 Unreal Engine 项目、项目源代码和资源目录，以及用户确认已经正常工作的菜单进入流程。原始设定文档保持不变；本次只生成开发文档，没有实施新的游戏功能。

文档中的任务默认均为待做，除非明确标记已有或用户已确认。未发现某类资源或变量只意味着本次检查未发现，不能证明所有素材包内部绝对没有相关实现。

### 如何使用这份文档
- P0 表示首个可玩版本必需的任务。
- P1 表示完整核心体验必需，但可以在首个可玩版本后完成。
- P2 表示深化体验或扩展玩法，依据测试反馈决定是否保留。
- 设定要求来自原文；新增建议是设计提案；暂定参数需要实测调整。
- 每个模块都有任务编号、前置依赖和验收要求。完成意味着实际运行通过验收，不只是创建资产或编译成功。
- 这是当前目标的完整工作分解基线。运动种类、制作规模和叙事表现方式确定后，仍需继续拆分镜头、动画和单个关卡任务。

## 02 游戏定位与核心循环

### 必须形成的体验
玩家扮演桑吉，带着父母留下的卢恩指南针登山。低海拔建立真实自然环境的压力，中段通过缺氧、理智和幻觉改变判断，高段引入重力异常和世界树奇观，终局将一路获得的线索与登山工具连接到三个选择。

完整循环为准备物资、观察路线与天气、移动和攀登、消耗身体与装备、发现线索和资源、评估继续或撤退、扎营恢复、解锁下一段路线。极限运动必须服务于路线选择、撤退或风险控制，不能只作为独立的表演动作。

### 产品边界建议
- G01 P0 暂按单人 PC 游戏设计，键鼠优先，后续适配手柄。这是新增建议，原文未规定平台和联机模式。
- G02 P0 选择第三人称作为首版主视角，沿用当前角色基础；需要近距离检查物品时使用查看界面。
- G03 P0 生存追求可读和可应对。资源短缺先限制行动，再产生持续伤害，玩家必须有获得信息和改善处境的机会。
- G04 P0 保留关键物品和剧情路线，随机性变化危险和补给，不随意破坏主线可完成性。
- G05 P1 规划章节式连续山地体验。地图是否无缝由实测加载和制作成本决定，不预先承诺超大开放世界。
- G06 P2 战斗、复杂建造、多人合作、全面制作与经济交易列为范围外扩展；没有明确玩法需求时不优先开发。

### 全游戏完成标准
从新游戏到三个结局都有可走通的路线；探索、身体、库存、营地、天气、运动和叙事互相影响；中途退出可以恢复；死亡与撤退有明确后果；最终打包版本通过完整流程，而不仅是在编辑器中能运行。

## 03 首个可玩版本与阶段顺序

### M1 基础生存与 HUD
- VS01 P0 在一段已有地形上确定出生点、短测试路线和返回点，不扩大地图。
- VS02 P0 实现生命、体力、饱食、水分、体温和统一伤害接口；氧气与理智先留数据接口。
- VS03 P0 做最小 HUD，能准确显示状态变化、交互提示和危险原因。
- VS04 P0 接入冲刺和体力耗尽限制，确认跑动消耗与站立恢复。
- 验收：同一路线步行与冲刺产生不同消耗，寒冷有可观察变化，暂停后状态停止推进，死亡不会重复触发。

### M2 物资与营地闭环
- VS05 P0 实现拾取、背包、食物、水壶、负重、快捷使用、帐篷和休息。
- VS06 P0 建立一次完整补给流程：拾取食物与水、行走消耗、正确消耗物品恢复、扎营保温、保存后继续。
- 验收：物品数量不复制、不负数；背包容量不足提示原因；休息结束后的时间、天气与状态一致。

### M3 探险与自然危险
- VS07 P0 布置营地、线索点、绕行路线、基础目标和固定落石教学事件。
- VS08 P0 加入一种天气变化和事件调度原型，提供提前预警和安全恢复窗口。
- 验收：玩家能够理解危险来源并选择绕行、等待或避难，首段路线可反复完成。

### M4 运动与高海拔
- VS09 P1 先做攀岩与绳降，再评估滑雪和滑降；加入缺氧、疲劳、伤病、装备耐久和理智。
- 验收：至少一种运动真正提供新的路线或撤退方式，错误操作有可预测的后果。

### M5 全章节与发布
- VS10 P1 完成村庄开场、三段山地区域、山顶神殿、三种结局、音画内容和全流程存档。
- VS11 P1 完成性能、无障碍、设置、打包、发布和回归测试。
- 不给出固定工期。先记录 M1 与 M2 的实际工作量，再估算后续内容规模与排期。

## 04 玩家动作与交互基础

依赖 当前第三人称角色与输入系统。后续库存、营地、运动与剧情都依赖本模块。

- ACT01 P0 整理玩家输入：移动、视角、跳跃、冲刺、蹲伏、交互、背包、快捷物品、暂停。区分按下、持续和释放。
- ACT02 P0 创建统一交互接口：显示名称、是否可用、不可用原因、执行操作和中断操作。
- ACT03 P0 使用距离、视线与角度判断交互目标；隔墙、过远和被 UI 遮挡时不能拾取。
- ACT04 P0 冲刺消耗体力；低体力取消冲刺，恢复后才允许再次冲刺，避免边界反复抖动。
- ACT05 P0 按移动状态统一协调普通行走、冲刺、受伤、负重、攀登和运动，防止多个模块争夺速度设置。
- ACT06 P0 定义动作占用规则。吃喝、搭帐篷、换氧气瓶期间能否移动、跳跃和取消，都需要明确。
- ACT07 P0 支持长按交互和进度提示；中断后是否扣资源以“操作提交点”为准，不由动画独自决定。
- ACT08 P1 检查坡面、阶梯、薄冰、狭窄路线、相机碰撞、落地和跌落伤害。
- ACT09 P1 做动作反馈：脚步、喘气、衣物声、手部动作、拾取和使用动画；占位动画只用于原型。
- ACT10 P1 手柄导航、键位重绑定、鼠标灵敏度、反转视角和 UI 关闭后的输入恢复。

验收要求 在背包、暂停、过场和正常游戏之间连续切换，人物不残留冲刺或失去输入；对同一物品连按交互只执行一次；高帧率与低帧率不改变移动和体力规则。

## 05 生存状态定义与关系

原设定明确要求饥饿、口渴、基础体温、氧气与理智。生命、体力、疲劳、湿度、伤病、负重和高海拔适应为补全玩法的新增建议。所有数值均为游戏抽象，不当作真实医学模拟。

### 主状态
- SUR01 P0 生命 Health：统一接受摔落、落石、持续环境和伤病伤害；归零只触发一次死亡。进食不默认立即恢复全部生命。
- SUR02 P0 体力 Stamina：短时间行动资源。跑动、跳跃、攀登消耗，休息恢复；饥饿、缺水、低温、疲劳和负重影响消耗或恢复。
- SUR03 P0 饱食 Satiety：值越高表示越饱。随时间和活动降低；长期不足先降低恢复，再影响生命或疲劳。UI 不混用“饥饿越高越差”的方向。
- SUR04 P0 水分 Hydration：随时间、活动和环境降低。饮水恢复；优先实现水源和水壶，不能只有一条无法补充的水分条。
- SUR05 P0 核心体温 CoreTemperature：采用可调的体温数值或归一化热状态；环境温度、风、湿衣、活动、遮蔽和保暖共同影响趋势。
- SUR06 P1 氧合 Oxygenation：代表身体氧气供应状态，受海拔、活动、适应与供氧影响。氧气瓶剩余量是独立资源，不能和身体氧合合并成一条数值。
- SUR07 P1 理智 Sanity：受剧情、幻觉、孤立和恶劣环境影响；缺氧可以放大表现。可恢复，不能让随机视效直接剥夺玩家所有控制。
- SUR08 P1 疲劳 Fatigue：长期消耗资源，值越高越差。睡眠恢复；减少最大体力或恢复效率，区别于短时体力。
- SUR09 P1 湿度 Wetness：衣物或身体淋湿程度，值越高越差；雨雪、涉水和出汗增加，遮蔽、干燥与热源降低。
- SUR10 P1 伤病 Conditions：流血、扭伤、骨折、冻伤和高海拔不适，以独立状态效果表示，分别规定持续、治疗和动作限制。

### 关系与规则
- SUR11 P0 确定每项取值范围、单位、初始值、危险阈值、恢复条件和存档字段，集中放在可调配置中。
- SUR12 P0 原型可用 0 至 100 的饱食、水分、体力与生命；危险阈值使用可调参数。不要在不同蓝图里散落固定数字。
- SUR13 P0 用统一时间步长更新生存状态。先合成环境与行为，再更新状态，再应用阶段效果，最后通知 HUD。
- SUR14 P0 设置持续伤害的宽限期和恢复出口，避免水分低、体温低、体力零同时锁死玩家。
- SUR15 P1 阈值进入和退出采用不同界线，避免在临界点频繁播报或重复施加效果。
- SUR16 P1 高海拔适应只作为简化游戏变量；剧情海拔由区域标定，不能直接把世界 Z 坐标当海拔。

## 06 生存系统实现与验收

依赖 玩家动作、时间系统和环境数据。HUD 读取结果，库存与营地调用恢复接口。

- SUR17 P0 创建独立生存组件，提供读取快照、修改状态、应用伤害、添加状态效果和状态变化事件。
- SUR18 P0 建立活动强度输入：静止、步行、冲刺、攀登、滑降。每项强度统一用于体力、饱食、水分与热量变化。
- SUR19 P0 建立统一移动修正结果，将伤病、负重、体温和疲劳合成为一个结果，不互相覆盖角色默认速度。
- SUR20 P0 加入调试面板：查看全部状态、环境输入、变化速率和当前效果，可快速设置测试值。
- SUR21 P0 暂停时停止生存与游戏时钟；加载和过场期间明确是否继续计算。休息快进使用单独规则。
- SUR22 P0 食物、饮水和治疗调用统一效果接口；设定使用条件、持续效果、冷却和重复叠加上限。
- SUR23 P1 设置详细身体页面：症状、来源、改善方法、身体部位、当前效果和持续时间。
- SUR24 P1 症状反馈关联实际状态。喘气来自高强度或缺氧，发抖来自寒冷，不能仅靠随机构造视觉噪声。
- SUR25 P1 不适、眩晕和视效可在设置中降低；减少闪烁和强制晃动后仍能通过文字和声音识别危险。
- SUR26 P1 统一恢复行为：休息恢复体力与疲劳、补给恢复饱食水分、治疗处理伤病、庇护缓解环境暴露。

### 必测场景
- SUR27 P0 比较同一时间内静止、步行和冲刺的状态变化，结果遵守活动系数。
- SUR28 P0 模拟体力耗尽、饥饿、缺水、低温和死亡，检查限幅、提示、恢复和只触发一次。
- SUR29 P0 对比 30、60 和较高帧率以及暂停恢复，状态不因帧率产生明显不同结果。
- SUR30 P1 测试多种效果同时作用、休息快进、跨地图、读取存档和濒死治疗，禁止数值溢出或无限恢复。

## 07 背包与物品数据

依赖 统一交互、生存效果和存档设计。首版建议使用列表或格子加重量上限；俄罗斯方块式体积拼装列为 P2。

- INV01 P0 定义物品模板：稳定 ID、名称、分类、描述、图标、模型、单件重量、最大堆叠、可用操作和效果配置。
- INV02 P0 定义物品实例：实例 ID、模板 ID、数量、耐久、容器剩余量、装备状态与附加数据。唯一装备不能只按名称存档。
- INV03 P0 分类包含食物、水与容器、药品、帐篷与睡袋、衣物、登山工具、氧气设备、照明、材料和剧情物品。
- INV04 P0 实现添加、移除、合并、拆分、转移、使用和丢弃接口；全部变更验证数量与容量。
- INV05 P0 同一次拾取必须原子完成。背包成功加入后才移除世界物品，失败时保留世界物品并提示原因。
- INV06 P0 支持满背包、超重、受伤、动作占用等不可执行原因。轻微超重可以允许并施加代价，硬上限需要清楚说明。
- INV07 P0 负重同时包含背包和已装备物品，避免把装备穿上后重量消失。水壶按空壶与剩余水量计重。
- INV08 P0 使用结束才扣物品或在明确提交点扣除。取消动作、死亡和读档后不能重复获得效果。
- INV09 P0 快捷栏保存物品引用或类别规则，最后一个物品用完后显示空位；不能生成免费的物品副本。
- INV10 P1 支持营地储物箱、剧情容器与尸体回收；不同容器共用转移接口。
- INV11 P1 明确关键物品政策。建议卢恩指南针等关键物品不可误丢弃、不可被灾害销毁，并明确是否计重。
- INV12 P2 食物变质、细致体积占用、容器嵌套和多种品质属性，依据体验收益决定是否加入。

验收要求 连续拾取、拆分、使用、丢弃、跨地图和保存读取后，物品总数守恒；丢弃物品不会穿透地面；物品缺失时存档有兼容回退和明确日志。

## 08 食物饮水与首版物品清单

物品数量与效果为起始内容建议，不是最终平衡参数。先完成少量可玩物品再扩充品类。

### 首版必需物品
- ITEM01 P0 能量棒：可堆叠、恢复饱食、短使用动作，作为第一件教学补给。
- ITEM02 P0 干粮：恢复量和重量区别于能量棒，展示出发准备的选择。
- ITEM03 P0 水壶：独立容量，喝水消耗剩余量，空壶不能使用，但可以补充。
- ITEM04 P0 密封饮用水：可拾取并饮用，或补充水壶；两种路径不得重复计算水量。
- ITEM05 P0 帐篷：可部署与收回，关联同一个实例和耐久，部署后不能同时留在背包。
- ITEM06 P0 睡袋：影响休息质量和保暖，首版可以仅作为营地必备装备。
- ITEM07 P0 简单急救包：处理一种明确伤害效果，不能同时无条件治愈全部状态。
- ITEM08 P0 头灯：首版提供基本照明与开关，电池消耗可在 P1 加入。
- ITEM09 P0 卢恩指南针：剧情与导航关键物品，显示目标方向或线索响应。

### 后续物品
- ITEM10 P1 氧气瓶与面罩：安装、启用、关闭、流量档位、剩余资源和更换动作。
- ITEM11 P1 冰镐、冰爪、安全带、绳索、岩钉与锁扣：分别对应运动能力，不只是不同图标。
- ITEM12 P1 保暖外套、手套和鞋：保暖、重量、湿度与耐久形成选择。
- ITEM13 P1 炉具、燃料、锅具和点火工具：共同实现化雪或热食；无燃料不能凭空得到热水。
- ITEM14 P1 绷带、夹板与止痛物品：分别处理流血、骨折与症状，定义治疗后剩余风险。
- ITEM15 P1 备用电池、修理材料、滑雪板和救援信标，按实际加入的玩法提供。

### 水源与食物规则
- FOOD01 P0 布置可识别的饮水补给点，交互时显示补充量、容量和不可用原因。
- FOOD02 P1 雪不能直接无限恢复安全饮水；化雪需要时间、燃料和容器。
- FOOD03 P1 设置安全水、待处理水和受污染水，净化作为明确行动；是否加入疾病由平衡测试决定。
- FOOD04 P1 使用生存物品必须有声音、动画或进度反馈；后台效果与动作中断规则保持一致。

## 09 装备负重与准备阶段

依赖 库存、身体状态和运动模式。装备的价值在于改变能力与风险，而不是堆叠无意义属性。

- EQ01 P0 规定装备槽位：身体、手、脚、背包、头部照明、工具与特殊设备；首版只开放实际有功能的槽位。
- EQ02 P0 背包提供容量和重量限制；切换背包时检查原有物品是否能够保留，不自动删除溢出物品。
- EQ03 P0 装备保暖、负重和移动修正统一交给身体与动作模块结算。
- EQ04 P1 冰爪提高冰面稳定或允许特定路线，冰镐支持攀登与制动，绳索支持保护或下降。
- EQ05 P1 定义耐久消耗、损坏症状、修理材料和维修地点，避免耐久只是定时减少的税。
- EQ06 P1 衣物和背包模型按装备状态显示；检查骨骼兼容、穿模、物理抖动、动画和远距离 LOD。
- EQ07 P1 出发准备页面提供预计路程、天气和物资摘要，让玩家权衡更多补给与更高负重。
- EQ08 P1 装备损坏前预警；关键运动途中不通过随机瞬间损坏直接制造无法回避的死亡。
- EQ09 P2 高品质、特殊装备和父母留下的装备，只在有明确能力差异时加入。

验收要求 更换装备后保暖、负重和可用动作立即一致；保存读取后装备实例与模型一致；装备损坏的限制可以解释、可以恢复；背包外观不被误认为库存本体。

## 10 帐篷营地与休息

依赖 库存、环境、时间、存档。帐篷提供庇护，睡袋提高恢复，炉具消耗燃料；三者分开建模。

- CAMP01 P0 实现帐篷放置预览，检测坡度、空间、地面支撑、碰撞、危险区和剧情禁放区，显示失败原因。
- CAMP02 P0 部署与拆除需要时间，并允许取消；完成前不生成正式帐篷，完成后不保留背包副本。
- CAMP03 P0 庇护区计算挡风和避雨效果，不能只靠一个画面里可见的帐篷模型。
- CAMP04 P0 营地交互包含进入、休息、收回、查看状态和保存；首版可使用简洁面板。
- CAMP05 P0 休息选择时长，预览饱食、水分、疲劳和温度趋势，危险时拒绝休息或清楚说明风险。
- CAMP06 P0 快进时间同时更新天气、燃料和状态；不能只跳过日夜画面而让身体完全不消耗。
- CAMP07 P0 暴风、受伤恶化和危险接近可以打断休息；必须有醒来后的反馈与行动窗口。
- CAMP08 P0 帐篷保存实例 ID、位置、耐久、储物和状态，读档后与背包不重复。
- CAMP09 P1 固定废弃营地提供故事线索与资源，有风险和资源限制，不能成为无限补给点。
- CAMP10 P1 炉具、化雪、热食、装备晾干、维修与睡袋保温，逐项连接实际消耗。
- CAMP11 P1 帐篷受风损坏或埋雪时表现清楚；不能在卸载区域中静默销毁唯一营地。
- CAMP12 P2 自由大型建造、复杂营地装饰与扩张暂不作为核心目标。

验收要求 平地可放、陡坡和障碍不可放；拆装、保存、读取后实例唯一；连续休息不会无限回血或逃避所有消耗；玩家能明确判断何时扎营比继续走更合理。

## 11 HUD 与全部界面范围

HUD 是身体、环境、库存和目标的呈现层，不负责决定消耗规则。首版应先准确、可读，再美化。

### 常驻与按需显示
- UI01 P0 主 HUD：生命危险、使用中的体力、饱食、水分与冷热提示。正常状态可弱化，危险时展开；不要一开始铺满十条进度条。
- UI02 P0 中央交互提示：目标名称、按键、动作、距离限制、不可用原因和长按进度。
- UI03 P0 状态告警：名称、原因和可行措施，例如寒冷提示避风或扎营，不只显示红色图标。
- UI04 P0 快捷栏：选中物品、剩余数量、使用进度与冷却；不可用时展示原因。
- UI05 P0 临时通知：拾取、背包已满、物品用尽、保存成功或失败。相同通知合并，避免刷屏。
- UI06 P1 导航：方向、目标、海拔与天气趋势；卢恩罗盘的剧情异常不能混同于普通导航错误。
- UI07 P1 高海拔 HUD：身体氧合与氧气瓶余量分开显示；理智症状提示独立呈现。
- UI08 P1 身体页面：全部状态、湿度、疲劳、伤病与改善办法；减少常驻界面负担。

### 全屏与专用界面
- UI09 P0 背包：分类、排序、数量、重量、详情、使用、装备、拆分、丢弃和快捷绑定。
- UI10 P0 营地：帐篷状态、可休息时长、预期变化、危险警告和保存入口。
- UI11 P0 暂停：继续、设置、保存或加载、返回菜单和退出，明确未保存进度。
- UI12 P0 死亡与恢复：死因、最近存档、重试、读取和返回菜单；不让玩家停留在失控画面。
- UI13 P1 地图与日志：已探索路线、营地、线索、任务和自定义标记。
- UI14 P1 装备准备、治疗、制作与维修界面按实际玩法增加。
- UI15 P1 对话字幕、文档阅读、剧情选择、结局回顾和制作人员名单。
- UI16 P1 新游戏、继续、存档列表和设置与现有开始菜单接入；目前菜单设置内容不能自动视为完整设置功能。

## 12 HUD 数据连接与界面验收

依赖 生存、库存、输入与存档接口。首版 HUD 与生存逻辑可以同期完成，但不先制作整套精美空界面。

- UI21 P0 设置屏幕安全区、缩放、布局锚点和文本溢出处理；检查 1080p、1440p 与超宽屏。

- UI23 P1 告警具有冷却与严重度优先级；自然危险声、剧情对白和状态提示互相避免抢占。

左下或侧边放基础状态，中央只显示当前交互，底部放快捷物品，上方按需显示方向与任务。体力在消耗和未恢复时显示，状态正常时减少占屏；这种布局是可调整建议，不是已经确定的美术规范。

验收要求 HUD 和调试快照一致；保存读取后值立即正确；同一危险不会每帧提示；菜单反复打开关闭无重复绑定；长中文和更大字体不遮住操作按钮。

## 13 探险路线与世界内容

依赖 移动、导航、生存与目标系统。探索要产生信息、物资、路径或故事收益。

- EXP01 P0 布置起点、首个补给点、废弃营地、可返回路段和一处终点，构成首段完整路线。
- EXP02 P0 主路、捷径和避难路各有意义。捷径省时间但耗体力或要求装备，主路安全但消耗补给。
- EXP03 P0 制作地标与可读地形，不能只靠任务箭头导航；关键叉路提供方向依据。
- EXP04 P0 关键物资有最低保障，随机补给不是首段唯一通关条件。
- EXP05 P1 探索点类型包括父母营地、遗留记录、木质岩层、冰封生物、观景点、天然避难点与符文遗迹。
- EXP06 P1 已发现路线、营地和线索写入地图与日志，并保存发现状态。
- EXP07 P1 天气改变能见度、路线风险和部分可通行区域；每种变化都有预警与替代选择。
- EXP08 P1 关键路线遮挡或中断后必须存在撤退、绕行或等待方案，避免随机灾害封死唯一出口。
- EXP09 P1 长途返程与下山也是玩法：检查疲劳、补给、负重和绳降便利，避免登顶后只靠传送收尾。
- EXP10 P1 地形碰撞、草石阻挡、相机、冰面打滑、落差和加载区域按玩家路线验收。
- EXP11 P2 摄影、探索日志补全、观景奖励和可选挑战，不能挤占主要生存反馈。

验收要求 初次玩家能理解去哪里、为什么去、怎样回头；探索收益不强迫每个角落都搜完；从营地到营地的时间和资源消耗经过实测；未完成装饰的地形不能被视为关卡设计完成。

## 14 攀岩绳降与极限运动

原文明确硬核攀登，但没有给出完整运动清单。建议首选攀岩与绳降，滑雪或雪坡滑降作为下一阶段；翼装、滑翔和复杂特技作为可选扩展。

- SPORT01 P1 定义可攀表面和攀登路线，建立攀登进入、移动、停留、退出、失误与坠落状态。
- SPORT02 P1 攀登消耗体力，并受负重、寒冷、伤病、工具与表面影响；提供休息点和撤退方式。
- SPORT03 P1 检测手脚支撑点或采用作者布置路线，先选择可控方案，避免首版就做任意表面全程序攀岩。
- SPORT04 P1 冰镐和冰爪提供明确功能，进入冰壁前检查装备与状态，失败原因可读。
- SPORT05 P1 绳索实现锚点、挂接、长度限制、下降、收回与失败状态；首版采用受控长度与路线。
- SPORT06 P1 绳降相机、输入、速度控制、着地与退出；受伤和急停规则与体力一致。
- SPORT07 P1 绳索保护先实现可靠防坠逻辑，视觉绳索与保护结算分开；不要把昂贵绳物理作为必要前提。
- SPORT08 P1 雪坡滑降或滑雪实现进入、转向、制动、坡面速度、碰撞、摔倒和恢复，不直接沿用普通步行速度。
- SPORT09 P1 运动期间界面突出速度、体力、风险和关键操作；训练段逐步教授控制。
- SPORT10 P1 运动动作为路线服务，例如绳降返回营地、滑降逃离落石通道；测试是否真的增加决策。
- SPORT11 P1 为每项运动补齐动画、工具握持、脚部适配、地表音效、镜头舒适选项和存档安全点。
- SPORT12 P2 翼装、滑翔伞、复杂跳跃特技与排行榜，只有在地图和核心运动稳定后评估。

验收要求 无装备不能穿越专用路线；体力耗尽有明确后果和可恢复条件；跨运动状态不会卡死；高速碰撞不穿地；死亡、读档和切地图能安全恢复到可行动状态。

## 15 时间天气与环境服务

依赖 现有天空天气资源；生存、营地、灾害和叙事读取统一环境数据。

- ENV01 P0 建立游戏时钟、时间倍率、暂停与休息快进接口，区分现实秒和游戏时间。
- ENV02 P0 提供当前环境快照：区域、剧情海拔、气温、风速、降水、能见度、遮蔽与危险等级。
- ENV03 P0 设置晴天、降雪和暴风雪的可调预设，平滑转换；视觉天气与逻辑天气使用同一个来源。
- ENV04 P0 接入现有 Ultra Dynamic Sky 与 Weather Actor，只读取需要的参数；正式适配时再核对资源确切属性和版本。
- ENV05 P0 气温与风影响体温趋势，降水影响湿度；屋内与帐篷影响暴露程度。
- ENV06 P1 海拔、昼夜、风口、谷地和庇护所提供不同环境，避免全图永远相同温度。
- ENV07 P1 天气预报或观察信息可以不完全准确，但必须有稳定规则；罗盘剧情异常另行处理。
- ENV08 P1 休息和跨地图后天气状态连续，粒子、声音、天空和身体计算同步。
- ENV09 P1 天气与时间序列保存随机状态和当前阶段，读档不反复刷新出更好的天气。
- ENV10 P1 神话区域以环境修正层增加重力、金粉和异常脉动，不污染普通区域的数据。
- ENV11 P2 动态积雪、地表湿润、足迹与全面地形变形，按玩法和性能收益决定深度。

验收要求 同一暴风雪既降低能见度也影响逻辑环境；帐篷内外状态差异可测；快进和读取后不会出现天空是晴天而生存仍按暴雪计算。

## 16 随机事件调度与公平规则

依赖 环境、玩家状态、区域标签和存档。随机事件应该改变决策，而不是无预警地掷骰子杀死玩家。

- EVT01 P0 定义事件模板：ID、类型、适用区域、天气与海拔条件、触发权重、冷却、危险预算、预警时长和恢复条件。
- EVT02 P0 将事件分成随机自然事件、区域教学事件和固定剧情事件，分别记录来源。
- EVT03 P0 调度流程为收集可用事件、检查互斥和预算、选择事件、预警、激活、结算、冷却与恢复。
- EVT04 P0 使用世界种子与持久随机状态支持复现；保存事件阶段与已结算标记，避免读档重掷或重复奖励。
- EVT05 P0 同一区域限制同时运行的高危事件数量；刚脱离灾害、读档或教学期间有短恢复窗口。
- EVT06 P0 为玩家提供可行动的预警：碎石声、坡面裂纹、积雪断裂声、风向变化、可见扬尘或明确提示。
- EVT07 P0 预警时间根据移动速度与躲避距离实测，不能统一使用一个短倒计时。
- EVT08 P0 事件触发区不得直接覆盖出生点、安全存档点、对话区或刚加载出来的玩家。
- EVT09 P1 调度考虑附近安全点和可绕路线，不在唯一出口上连续生成无解危险。
- EVT10 P1 提供良性与中性事件：天气短暂转晴、发现旧补给、无线电片段、特殊足迹和远处异象。
- EVT11 P1 剧情事件抢占随机事件时明确取消或延后，剧情镜头期间不偷袭玩家。
- EVT12 P1 调试工具允许指定事件、种子、区域和阶段；记录触发理由及被拒绝理由。

验收要求 固定种子可复现测试；跨地图与保存读取不重复生成事件；危险之后有可恢复窗口；所有致命事件至少有清晰预警或作者定义的必然情节，并说明玩家控制边界。

## 17 灾害与事件内容清单

先完成落石，再扩展雪崩和滑坡。灾害的视觉规模与碰撞计算分开，优先保证玩法和性能。

- HAZ01 P0 落石：布置危险坡面、轨迹、预警石屑与声音，激活有限数量岩石，统一伤害和冲击，结束后清理。
- HAZ02 P0 落石避难点：可靠遮挡与绕行路线，避免看似能躲的石头或帐篷实际没有保护效果。
- HAZ03 P0 暴风雪事件：逐步降低能见度、增大风寒，提供避风与扎营策略，结束后恢复环境。
- HAZ04 P1 雪崩：定义源区、通道、到达时间和躲避边界；视觉用雪雾与大体量表现，伤害用可控推进范围。
- HAZ05 P1 雪崩后果：推倒、伤害、埋压或丢失非关键物资；单人埋压需要可恢复机制，避免没有互动的长等待。
- HAZ06 P1 滑坡：改变局部通行状态、迫使绕行，保存已发生变化；不能要求实时重建整座 Landscape。
- HAZ07 P1 薄冰与裂隙：表面征兆、重量或踩踏触发、下坠与自救；陷落后有救援或重试出口。
- HAZ08 P1 强风与冰面打滑：在特定区域影响平衡、行动和运动，玩家可以通过装备或路线应对。
- HAZ09 P1 装备故障与物资意外：提前表现磨损或质量问题，不随机销毁关键剧情工具。
- HAZ10 P1 神话雪崩：黑龙撞击触发，加入重力与金粉异常，采用作者编排的关键场景，并连接章节进度。
- HAZ11 P2 雷暴、地震、白化迷航、夜间异声和野生动物遭遇，逐项评估是否提供独特玩法。
- HAZ12 P1 每类事件都需要音效、粒子、碰撞、伤害、预警、结束、卸载和存档规则，不以单个特效资产作为完成。

验收要求 从预警到逃离全过程可连续测试；岩石高速不穿透玩家或地面；危险体积与视觉大致一致；雪崩结束后不残留隐形伤害；重复触发不持续累积物理 Actor。

## 18 氧气理智与幻觉

依赖 基础生存、环境、物品、事件与剧情阶段。原设定的 6000 至 8000 米是叙事分区标签，不在本规划中作为真实医学分区定义。

- PSY01 P1 身体氧合受到海拔区域、活动强度、适应和供氧影响，提供减速、休息、下降与使用氧气的应对。
- PSY02 P1 氧气瓶保留剩余量、开关、流量和装备条件；瓶空、未戴面罩和更换过程中反馈清楚。
- PSY03 P1 理智变化关联剧情暴露、环境压力与恢复地点；玩家至少能理解部分原因与改善办法。
- PSY04 P1 建立幻觉模板：视觉、声音、父母幻影、错觉路径和罗盘异常，按章节与身体状态选择。
- PSY05 P1 幻觉与真实物体分层。幻觉默认不产生真实碰撞、库存或永久存档，只有明确剧情规则允许例外。
- PSY06 P1 为判断真假提供线索：脚印、声音方向、符文反应、重复出现、记录矛盾或环境证据。
- PSY07 P1 错觉路径会诱导风险但不能成为无从判断的唯一解；需要回头、观察或寻找替代依据。
- PSY08 P1 视野扭曲、耳鸣、镜头与字幕表达分级；舒适设置降低特效后保留玩法信息。
- PSY09 P1 幻觉播放采用冷却和互斥，不与灾害关键预警和重要对白同时遮蔽全部信息。
- PSY10 P1 保存幻觉已见、线索已发现和剧情进度；读档后不重复播放每个首次镜头。
- PSY11 P2 幻觉改变解谜方式或提供可选线索，必须经过可理解性测试后扩大。

验收要求 缺氧能通过实际行动改善；理智低不是永久失败；玩家能够说明至少一种识别幻觉的依据；关闭强烈视觉效果后仍可完成所有路线。

## 20 三结局与神话法则

### 三个结局的制作任务
- END01 P1 牺牲结局：确认献祭、操作过程、父母灵魂解脱、世界异动停止、主角留在巅峰与结局演出。
- END02 P1 执念结局：抽取能量、父母醒来、世界树崩解、黑龙释放、末日下山与结局演出。
- END03 P1 凡人觉醒结局：发现牺牲骗局、获得破坏核心的能力或工具、击碎核心、金脉熄灭、黑龙离开与扶持下山。
- END04 P1 第三结局是否需要收集线索解锁，由剧情设计确定。建议有可理解的证据要求，不要求毫无提示地搜集全部收藏品。
- END05 P1 原文中第三结局使用登山工具或父母装备仍有备选表达。正式制作前确定唯一行动及前置铺垫。
- END06 P1 三个选择说明其已知代价，关键选择设置确认与结局前存档；执行后避免误操作切换结果。
- END07 P1 每个结局记录稳定 ID、已观看状态、字幕、跳过状态和制作人员名单，允许从结局前存档回看。

### 高段特殊法则
- MYTH01 P1 重力异常采用限定区域与阶段控制，分别定义跳跃、攀登、绳索、投掷物和相机行为。
- MYTH02 P1 世界树显露通过章节控制视觉、碰撞、路线与声音，改变路线时提供可走通的新出口。
- MYTH03 P1 黑龙以远景、声音和事件为首版表现建议。是否制作完整可战斗 Boss 尚未确定，不自动纳入必要战斗系统。
- MYTH04 P1 法则级雪崩兼容生存与运动，设置作者预警和可验证的逃离路径。

验收要求 三条分支均可完成、跳过和读取；结局前保存不丢失关键工具；最终下山是可操作段或明确镜头，两者选定后分别拆出动画、路线与字幕任务。

## 21 NPC 对话与叙事技术

原文提到 AI NPC 对话，但没有明确必须运行在线生成模型。建议关键主线对白先用固定剧情数据，在线对话列为可选增强。

- NPC01 P1 祭司对话制作：角色、对白树、镜头、字幕、声音、玩家选择和出发目标。
- NPC02 P1 父母通过记录、幻影与终局角色表现；分别规定是否可交互与是否属于真实世界。
- NPC03 P1 对话支持已读、跳过、继续、条件分支和日志回顾，主线信息不因玩家跳过而丢失任务状态。
- NPC04 P1 可选路遇角色、无线电联系与营地记录提供世界信息，先确定人数和功能再制作资产。
- NPC05 P1 对话期间身体与灾害是否暂停需统一规则。建议关键过场暂停致命随机事件，普通世界交互维持环境。
- NPC06 P2 若加入在线 AI NPC，限制可谈主题、角色知识与剧情阶段，提供断网回退、响应时限和费用上限。
- NPC07 P2 在线模型不能直接修改物品、伤害、任务或结局，只有经过验证的游戏操作接口可改变状态。
- NPC08 P2 记录用户是否同意联网、隐私提示与可关闭选项；没有联网也应能够完成主线。

验收要求 主线对白完全可离线完成；角色不会提前泄露尚未发现的结局；跳过与重读不重复奖励；NPC 若加入在线能力，其失败不会阻塞存档和章节推进。

- SAVE12 P1 结局前独立存档，通关后继续与新游戏互不覆盖。

验收要求 在拾取、使用、扎营、事件阶段、跨地图和任务推进之后保存退出再读档，数量与状态完全对应；模拟写入失败或坏档可恢复；新游戏不继承上一局的菜单或剧情旗标。

## 23 Unreal 实现结构与数据契约

以下是建议结构，均未在本次新增到项目。实现时根据现有蓝图和 C++ 分工调整，不要求一开始引入复杂框架。

- TECH04 P0 GameInstance 可协调跨地图会话，实际长期数据持久化到 SaveGame；不要仅靠一个 EnteringGame 布尔值管理整局。
- TECH05 P0 物品、生存参数、天气、灾害、任务与日志使用 DataAsset 或 DataTable 等数据驱动配置，选择一种主方案并保持一致。
- TECH06 P0 固定契约包括 GetSurvivalSnapshot、ApplyEffect、TryAddItem、TryUseItem、CanInteract、GetEnvironmentSnapshot 与 SaveSession 等职责；命名仅作示例。
- TECH07 P0 物品、容器、营地、任务、事件和章节使用稳定 ID，保存时不依赖临时 UObject 引用或易变名称。
- TECH08 P1 建议项目自有资源放到 Content/YggdrasilsPeak 下，按 Characters、Systems、Items、UI、World、Narrative、Data 与 Tests 分组；现有资源不在这次规划中迁移。

- TECH10 P1 热点逻辑、存档和性能敏感运算按需要使用 C++，内容调参与演出适合蓝图；先以可维护和可测试为标准。
- TECH11 P1 为接口维护字段说明、单位、事件时机、失败结果和存档版本，不让库存与 HUD 用不同数据含义。
- TECH12 P1 引擎升级、插件更新和重构单独成任务，先备份与测试，不与核心玩法提交混在一起。

验收要求 替换某个 HUD 或物品模型不会改变核心规则；从调试工具和正式交互触发同一操作得到同一结果；所有跨关卡数据都有明确所有者和恢复入口。

## 25 性能质量与发布工作

## 26 依赖关系与下一批具体任务

### 关键依赖链
角色与交互 → 生存状态和环境快照 → 最小 HUD → 拾取与库存 → 食物饮水 → 帐篷休息 → 存档 → 探索路线与落石 → 随机调度 → 攀岩绳降 → 高海拔氧气理智 → 全章节与三结局 → 打包验收。

环境、存档与任务的数据结构要较早设计，其完整内容可以逐步补齐。美术可以随着可玩模块推进，但每次要验证整合结果。

### 建议立即实施的第一批
- NEXT01 建一个可复现的短测试路线，记录出生位置、终点和测试时长。
- NEXT02 明确状态方向和单位，建立生命、体力、饱食、水分、体温配置。
- NEXT03 创建生存组件与事件，加入调试快照和快速设置测试值。
- NEXT04 接入冲刺消耗、停止恢复和体力耗尽限制。
- NEXT05 做最小 WBP_GameHUD，显示五项基础状态、告警和交互提示。
- NEXT06 建环境适配接口，用晴天与寒冷测试值验证身体变化，再接入当前天气资源。
- NEXT07 实现能量棒、水壶和拾取接口，验证消耗物品与状态恢复只发生一次。
- NEXT08 建最小背包页面，支持数量、重量、使用、丢弃与快捷绑定。
- NEXT09 加入帐篷与休息，打通饱食水分消耗、避风保温和恢复。
- NEXT10 加入一次安全保存与读取，验证同一物品和帐篷实例没有复制。

### 这批的交付物
一段能够实际跑通的生存路线、可调状态配置、可用 HUD、少量物品、背包、帐篷和存档。美术可以仍是占位，但每项行为都能够测试并看到反馈。

本次建议先从 NEXT02 至 NEXT05 开始。HUD 有很多后续内容，但第一批只做身体状态、交互和告警，不需要先把整套地图、任务、装备和治疗界面全部画完。

## 27 未决设计与范围控制

下列事项不阻塞基础生存原型，但在对应模块开始前需要确认。此文档先按单人第三人称、叙事驱动、小范围首段原型推进。

- DEC01 平台、目标硬件、目标帧率和画质基线，决定地图、天气和灾害规模。
- DEC02 总游戏时长、地图分段与可回访程度，决定物资间隔、存档点和内容生产量。
- DEC03 真实生存强度与叙事容错程度，决定消耗速度、死亡代价与是否提供难度档。
- DEC04 运动主项是否只包含攀岩、绳降和滑降，其他运动不能在未确定前默认为必做。
- DEC05 背包采用列表重量、格子重量还是体积拼装；建议首版前两者选一种。
- DEC06 开放背包是否暂停、营地是否自动保存、关键剧情是否停止身体消耗。
- DEC07 理智是否为显式数值，还是症状等级；建议详细页面可查，常驻 HUD 按风险显示。
- DEC08 第三结局的线索要求、破坏核心工具和最终下山表现，必须在章节制作前锁定。
- DEC09 AI NPC 是普通游戏对话还是在线生成对话；在线功能不作为主线依赖。
- DEC10 是否有动物、敌人和战斗；原设定不足以推导必须有完整战斗系统。
- DEC11 饮水净化、食物腐坏、伤病复杂度、制作系统和装备品质是否带来足够决策收益。
- DEC12 是否做联网、多人、赛季、排行榜和收费内容；这些均不在当前首版承诺中。

### 防止范围失控
每增加一个状态，必须回答它怎样变化、玩家怎样观察、怎样处理、影响哪种决策、怎样保存和怎样测试。每增加一种运动，必须有专用路线、输入、动画、失败与恢复。每增加一种灾害，必须有预警、应对、结束与存档。
