## 1. Which Unreal MCP servers exist, and which expose Sequencer / Level Sequence tools?

### Takeaway
There are now dozens of Unreal MCP servers. For Sequencer work, Epic's own UE 5.8 toolsets are the most complete verified option (about 140 core Sequencer tools plus keyframing, bindings, Control Rig, outliner and Anim Mixer toolsets), and this project already has them. Among third-party servers, only a few name Sequencer tools: ChiR24/EngineWire (`manage_sequence`), Flux-Point (fork-style, `manage_sequence`), StraySpark (commercial, "skeletal Sequencer tracks"), Claireon (via Python), the hosted Flopperam/Aura "Flop MCP" (`sequencer_edit`), echoulen claude-unreal (27 Sequencer tools), ATDev uemcp, and unreal-mcp-additional-tools. The early, popular community servers (chongdashu, runreal, Flopperam local, kvick) have **no** Sequencer tools.

### Cited Findings

## 2. Has Epic shipped official AI assistant / MCP / agent features in UE 5.6, 5.7, 5.8 (and 5.9)?

### Takeaway
Yes, in stages. **5.6 (2025):** the Epic Developer Assistant shipped as a web or companion tool. **5.7 (Nov 2025):** an in-editor AI Assistant panel for Q&A, C++ snippets and step-by-step guidance (it does not act on the editor). **5.8 (June 2026):** the experimental **Unreal MCP** plugin plus the **Toolset Registry / AllToolsets**, which let external agents (Claude Code and others) drive the editor, including about 340 Sequencer tools. **5.9 Preview (2026-11-09):** **Unreal Assistant** (an in-editor panel that hosts Claude Code, Codex, Cursor or OpenCode, with tool access levels), more toolsets, Unreal Canvas, and AnimGen/Kimodo animation generation that can land directly in Sequencer.

## 3. Claude Code skills, plugins or subagent packs for Unreal Engine or game cinematics

### Takeaway
Epic publishes an official Claude Code plugin, **unreal-engine-skills-for-claude-code**, in Anthropic's official marketplace. It teaches Claude how to drive Epic's Unreal MCP. Several community skill packs target cinematics specifically. Schepetkov's MIT `ue-cinematics` skill (UE 5.8, Sequencer over Epic MCP) is the closest match to this project. None of them claims proven cutscene-production speed-ups.

### Cited Findings
- **EpicGames/unreal-engine-skills-for-claude-code-plugin** (official): the `unreal-mcp` skill covers spawning and transforming actors, properties, Blueprints, Widgets, Materials, Niagara, Control Rigs, **Sequencer**, Behavior Trees, GAS and Live Coding. It uses the three meta-tools (`list_toolsets`, `describe_toolset`, `call_tool` with `toolset_name`, `tool_name`, `arguments`). Its own example is `SequencerTools.create_level_sequence`. It cites "hundreds of tools across 30+ toolsets". Safety rules: save before and after bulk changes ("MCP edits are not always undoable"), serialize dependent calls, treat any non-explicit success as a stop, and check for PIE. It also has an optional `unreal-mcp-proxy` and companion skills `create-toolset` and `unreal-skill`. — [SKILL.md](https://github.com/EpicGames/unreal-engine-skills-for-claude-code-plugin/blob/main/skills/unreal-mcp/SKILL.md)
- Install with `/plugin install unreal-engine-skills-for-claude-code@claude-plugins-official`. — [Claude Directory](https://www.claudedirectory.org/plugins/unreal-engine-skills-for-claude-code). Listed on Anthropic's marketplace with the example prompt "Set up a montage in Sequencer for the intro cutscene". — [claude.com marketplace](https://claude.com/marketplace/plugins/unreal-engine-skills-for-claude-code)
- **Schepetkov/claude-skills-game-UE** (MIT, 2 stars, 70 commits, targets UE 5.8, checked against a 5.8.1 source tree): skills `ue-cinematics` ("Directing in-engine cutscenes and dialogue": beats, blocking, 180° axis, coverage kit with lenses, cutting on line events, creature reveals, FK Control Rig additive layers and baking, runtime playback; "Sequencer over MCP (339 tools)"), `ue-mcp`, `ue-lighting`, `ue-ui`, `ue-performance`, `ue-assets`, `ue-networking`, `meshy-3d-generation`, `agent-workflow`, `retro`. — [GitHub](https://github.com/Schepetkov/claude-skills-game-UE)

## 5. Most reliable way today for an agent to author a Level Sequence via Python; limitations and breaking changes 5.5–5.8

### Takeaway
The most reliable path in 5.8 is to call **Epic's own `SequencerTools` / `SequencerKeyframingTools`** through Unreal MCP. They are thin, tested wrappers over `LevelSequenceEditorSubsystem`, `MovieSceneBindingExtensions` and similar APIs, maintained by Epic for 5.8. Raw editor Python via remote execution (already used in this project) is the fallback for anything missing. The main breaking change is that **spawnable creation moved from `MovieSceneSequenceExtensions` to `LevelSequenceEditorSubsystem` (deprecated in 5.6), and the subsystem requires the sequence to be open/focused in Sequencer.**

### Cited Findings
- Epic's toolset implements camera creation as `unreal.get_editor_subsystem(unreal.LevelSequenceEditorSubsystem).create_camera(spawnable)`, which returns `(binding, camera_actor)`. Camera cuts are set by building `unreal.MovieSceneObjectBindingID()`, setting `"Guid"`, and calling `section.set_camera_binding_id(binding_id)`. Tracks are added with `binding.add_track(track_type)`. Animation goes on via `set_section_animation(section, anim_sequence_path)` after adding a `MovieSceneSkeletalAnimationTrack`. Keys go on via `add_key_float(section, 'Location.X', frame, value, interpolation)`. Event tracks via `add_event_trigger_section(MovieSceneEventTrack)`. — [local sequencer.py](file:///E:/UE5.8/UE_5.8/Engine/Plugins/Experimental/Toolsets/AnimationAssistantToolset/Content/Python/animation_toolset/toolsets/sequencer.py); [local keyframing.py](file:///E:/UE5.8/UE_5.8/Engine/Plugins/Experimental/Toolsets/AnimationAssistantToolset/Content/Python/animation_toolset/toolsets/keyframing.py)
- Epic ships test files for these toolsets (`test_sequencer_toolset.py`, `test_sequencer_control_rig.py`, `test_sequencer_import_export.py`, `test_sequencer_conditions.py`), which suggests they are exercised in Epic CI. — [local tests folder](file:///E:/UE5.8/UE_5.8/Engine/Plugins/Experimental/Toolsets/AnimationAssistantToolset/Content/Python/animation_toolset/tests/). Epic also ships `sequencer_examples.py` in SequencerScripting. — [local file](file:///E:/UE5.8/UE_5.8/Engine/Plugins/MovieScene/SequencerScripting/Content/Python/sequencer_examples.py)
- **Deprecation:** `UMovieSceneSequenceExtensions::AddSpawnableFromInstance` is flagged deprecated ("use AddSpawnableFromInstance in the Level Sequence Editor Subsystem"). — [Epic API docs](https://dev.epicgames.com/documentation/unreal-engine/API/Plugins/SequencerScripting/UMovieSceneSequenceExtensions/AddSpawnableFrom-). Python reference for the subsystem: [LevelSequenceEditorSubsystem](https://dev.epicgames.com/documentation/en-us/unreal-engine/python-api/class/LevelSequenceEditorSubsystem)
- **Version conflict:** a forum user reports the deprecation in **5.6** — [forum, 2025-09-22](https://forums.unrealengine.com/t/add-spawnables-to-sequence-in-5-6/2658807). Another thread reports the sequence-level call already breaking in **5.5** — [forum](https://forums.unrealengine.com/t/ue5-5-unreal-moviescenesequence-add-spawnable-from-instance/2136656)
- **Must be open:** the subsystem errors with "AddSpawnableFromClass requires that the requested sequence … be open in the editor". The workaround is `unreal.LevelSequenceEditorBlueprintLibrary.open_level_sequence()`, then `get_editor_subsystem(LevelSequenceEditorSubsystem).add_spawnable_from_class()`, then `close_level_sequence()`. Possessables can be added without opening. No Epic staff reply. — [forum](https://forums.unrealengine.com/t/add-spawnables-to-sequence-in-5-6/2658807)
- Other reported friction (thread titles): "Deprecated set_property_name_and_path works while replacement does not" — [forum](https://forums.unrealengine.com/t/depricated-set-property-name-and-path-works-while-replacement-does-not/2690780); "Alternative to deprecated get_bound_objects?" — [forum](https://forums.unrealengine.com/t/alternative-to-deprecated-get-bound-objects/1606485/3); "GetSpawnableCount() always returns 0" — [forum](https://forums.unrealengine.com/t/getspawnablecount-always-returns-0/2512919); "Configuring a spawned CineCamera in a LevelSequence using Python" — [forum](https://forums.unrealengine.com/t/configuring-a-spawned-cinecamera-in-a-levelsequence-using-python/2712964); crash when adding components to a despawned spawnable (UE 5.7) — [forum](https://forums.unrealengine.com/t/crash-when-adding-actor-components-to-a-spawnable-actor-in-sequencer-while-it-is-despawned-ue-5-7/2709569); MRQ still-image automation broken in 5.5.3 — [forum](https://forums.unrealengine.com/t/movie-render-queue-still-image-automation-not-working-in-ue-5-5-3/2329626)
- Epic's 5.8 toolset still exposes `set_property_name_and_path` (despite the deprecation report) and offers `convert_to_custom_binding`, which reflects the newer custom-binding model. — [local sequencer.py / custom_bindings.py](file:///E:/UE5.8/UE_5.8/Engine/Plugins/Experimental/Toolsets/AnimationAssistantToolset/Content/Python/animation_toolset/toolsets/)
- 5.9 renames marked frames to "marks and mark ranges", which may affect `add_marked_frame`-style calls. The Python Foundation Packages plugin is removed. — [UE 5.9 release notes](https://dev.epicgames.com/documentation/unreal-engine/unreal-engine-5-9-release-notes)
- General MCP reliability issues seen in 5.8: models "acted before inspecting", retried in loops, "claimed changes were verified when they weren't applied", argument names were inconsistent across toolsets, and results were silently truncated. — [Algosyntax](https://store.algosyntax.com/blog/ai-assistants-mcp-unreal-engine-5-8). Epic's own skill warns that some failures "return without an exception". — [Epic SKILL.md](https://github.com/EpicGames/unreal-engine-skills-for-claude-code-plugin/blob/main/skills/unreal-mcp/SKILL.md)
- Cutscene Agent failure modes (any LLM): omitted pipeline steps (skipped audio or face calls), hallucinated names or animation IDs, overlapping animations, and gaps with no active camera. Three-character scenes were the hardest tier. — [arXiv 2604.25318](https://arxiv.org/html/2604.25318v1)

### Inferences
- Recommended pattern: (1) open the sequence first, (2) create spawnables through the subsystem or Epic's tools, (3) add transform, animation, audio and event tracks plus keys, (4) set the camera cut, (5) **read back** (`get_tracks_on_binding`, `get_keys`, `get_section_range`) and take a screenshot via scene capture before declaring success, (6) save with AssetTools. Bundling a whole beat into one sandboxed Python script (the "programmatic tool") or one custom toolset call reduces the per-call failure and latency problems.
- Event tracks: Epic's tool adds trigger sections, but binding them to a Director Blueprint endpoint was not seen in the toolset. For gameplay-interactive beats, a C++/BP "story beat" actor driven by a sequence or StateTree may be sturdier than Sequencer events.

### Gaps
- Epic's official 5.6, 5.7 and 5.8 release-note lines for Sequencer Python deprecations were not read directly, so the 5.5 vs 5.6 deprecation version is unresolved.
- I did not check whether Epic's `add_spawnable_from_class` tool opens the sequence automatically.

## 6. Real reports of solo developers using AI agents plus MCP for cutscenes or game content

### Takeaway
There are real reports of solo developers shipping whole jam games with Claude Code driving Unreal through Epic's MCP. Some are on 5.9 for the Epic AI MegaJam. I found **no devlog of an AI-built Sequencer cutscene in a shipped game**. The one rigorous cutscene study (Cutscene Agent) shows strong tool-use correctness but only mid-level cinematic quality (best 50.2/100, from Claude Opus 4.6). The consistent lessons: give the agent clear, checkable tasks, keep the human as director, verify claims, and expect slow turns and high token use.

### Cited Findings
- **FINAL CUT (Mullin-Works, 2026 Epic AI MegaJam):** built in 3 days by one person plus Claude Code driving the editor via MCP, using AgentCraft (the developer's own plugin) plus "Epic's experimental ModelContextProtocol tools". The agent built Blueprint logic (generated from a text DSL), levels, lights, cameras (a follow spot and a 2.35 letterbox when the camera rolls), materials, UI and procedural audio. It also ran an automated PIE playtest after every change (about 60 commits, about 20 packaged builds). Failures: some editor operations didn't work (an audio volume node couldn't be bound), automated tests skip the UMG menu, and the agent misdescribed TTS voices. Lessons: "two honest attempts … then choose a simpler design", human keeps the director role, verify claims. — [itch.io devlog #2](https://mullin-works.itch.io/final-cut/devlog/1776695/devlog-2-how-one-human-and-an-ai-agent-made-final-cut-in-3-days)
- **Directors Cut (BerailGames):** "My team is me plus Claude Code, connected straight into Unreal Engine 5.9 through Unreal MCP, so the agent can write C++, build levels, and play-test". It is a camera-driven game, not cutscenes. — [itch.io devlog #1](https://berailgames.itch.io/directors-cut/devlog/1774754/devlog-1-three-games-in-30-hours-and-the-one-that-stayed)
- **Puget Systems hands-on (2026-07-09, UE 5.8, Claude Opus 4.8):** a six-room greybox in about 5 minutes and a light-toggle Blueprint worked. Switching to walking controls failed (unplayable; a "fixed" claim changed nothing). A PCG city was faked with placed meshes, and the model later admitted it could not build PCG graphs from scratch. Turns took 5–15+ min, and about 15% of a weekly token allotment went in one morning. No Sequencer tests. Conclusion: use MCP "to speed up iteration, not to fill gaps in knowledge". — [Puget Systems](https://www.pugetsystems.com/blog/2026/07/09/unreal-engine-mcp-hands-on-testing-ai-inside-the-editor/)
- **Magnopus** (studio) wrote an artist's perspective on UE plus MCP workflows. — [Magnopus blog](https://www.magnopus.com/blog/unreal-engine-mcp-an-artists-perspective-on-the-future-of-3d-workflows) (not read)
- **Cutscene Agent benchmark (CutsceneBench, 65 scenarios, 8 LLMs):** Claude Opus 4.6 scored 100% on tool selection, parameter validity, call completeness and dependency compliance, and 96.4% on camera coverage. Narrative and cinematic quality (Gemini judge, out of 100): Opus 50.2, GPT-5.4 42.4, Sonnet 4.6 41.7, MiniMax M2.5 25.8. "Cinematographic quality was the most discriminating dimension." — [arXiv 2604.25318](https://arxiv.org/html/2604.25318v1)
- A forum report says a fast model followed an exact camera instruction ("move this camera by this amount") in about half a minute. — [Algosyntax](https://store.algosyntax.com/blog/ai-assistants-mcp-unreal-engine-5-8)
- A separate 72-hour project found Claude Code and Codex "not reliable at vision-based tasks like placing lanterns, lights, and props around a 3D scene". — [daily.dev summary](https://daily.dev/posts/i-built-my-dream-game-in-72-hours-assets-by-ai-gameplay-by-claude-code-eedcr1c11) (secondary)

### Inferences
- The evidence supports the agent doing **mechanical assembly** (create sequence, bind actors, lay tracks, place keys from a written shot list, set cuts, wire events, render previews), while the human writes or approves the shot list and judges framing. That matches this project's existing "verify by measurement, user makes the visual call" rule. A 5–10× speed-up on assembly is plausible, but none of these sources measured cinematic throughput, so this is an inference only.
- Multi-character staging (NPC partners such as Nima or the Kovac team) is the known weak spot (the S4 tier was hardest in Cutscene Agent). Prefer reusable staging templates over free-form placement.

### Gaps
- No Reddit, Hacker News or YouTube first-hand accounts of AI-authored Sequencer cutscenes were found in the searches made. Reddit-specific searches returned registry pages instead.
- No quantified before/after time savings for cinematics from any source.
